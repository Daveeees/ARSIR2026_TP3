Exercice 2 : susurrez à l'oreille du serveur

Q1. Réponses aux requêtes :

1. GET /\r\n
Réponse : Le serveur renvoie directement le code HTML si le protocole HTTP/0.9 est supporté, ou une erreur 400 Bad Request sur les serveurs récents exigeant une version HTTP valide.
Explication : Syntaxe historique de HTTP/0.9 (requête simple sans version ni en-têtes).

2. GET / HTTP/1.1\r\n\r\n
Réponse : 400 Bad Request
Explication : En HTTP/1.1 (RFC 2616), le champ d'en-tête "Host:" est obligatoire. Son absence entraîne une erreur 400.

3. GET / HTTP/1.1\r\nHost:perdu.com\r\n\r\n
Réponse : 200 OK avec les en-têtes de réponse et le contenu HTML de la page.
Explication : Requête HTTP/1.1 complète et bien formée.

À quoi sert le champ Host ?
Le champ Host permet le virtual hosting (hébergement virtuel). Il indique au serveur quel site web le client souhaite consulter parmi tous les sites hébergés sur la même adresse IP et le même port.
